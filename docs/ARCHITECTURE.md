# Architecture

approximately is a local-first flight recorder and MAST failure-attribution
toolkit. Everything is stdlib-only in the core; the only optional extras are
the LLM judge (`openai`) and framework adapters (`contrib/`, installed per
framework). This is the module map: what each layer owns and how evidence
flows through it.

## The evidence pipeline

```
agent run
   │  Recorder seam (5 lines) or a contrib adapter
   ▼
recorder.py ──► trace.py ──► store.py
                │              │  atomic saves (temp + os.replace),
                │              │  per-id locks, ledger appends
                ▼              ▼
           integrity.py   ledger.py
           per-step sha256/HMAC chain + evidence block
                          ledger append-only store history
```

- **`trace.py`** — the `Trace`/`Step` data model; the unit of evidence. One
  trace = one agent run; steps are tool calls, thoughts, responses.
- **`recorder.py`** — the `Recorder` context manager and the `@agentstep`
  decorator. Records every step and stamps the integrity chain on exit.
- **`store.py`** — `TraceStore`, one JSON file per trace. Atomic writes;
  concurrent same-id saves serialize; optional ledger appends under
  `APPROXIMATELY_LEDGER=1`.
- **`integrity.py` / `ledger.py`** — tamper evidence. Unkeyed sha256 chains
  detect accidents; HMAC chains (signing key) survive adversaries; the
  append-only ledger catches rolled-back traces. `verify --all` gates a
  whole store in CI.

## Attribution

```
run_rules(trace)
   ├─ meta["prose"]?  prose.py (7 prose detectors + the cycle detector)
   └─ else            detectors.py (15 tool detectors)
        ▼
attributor.py ──► FailureReport
   LLR Bayesian fusion: MAST base-rate prior + summed evidence LLR
        ▼
report.py / mermaid.py / sarif.py / metrics.py
```

- **`detectors.py`** — the tool-family rules (repetition, cycles, missing
  verification, derailment, role violations, ...) and `run_rules`, the
  dispatcher: prose-shaped records (`meta["prose"]`, set by the MAST-Data
  converter) run the prose family *exclusively* — their (tool, args)
  fingerprints are meaningless, and tool rules would fire on every
  same-agent turn pair.
- **`prose.py`** — the prose family: near-verbatim repetition,
  trajectory restart (opening-turn recurrence), derailment, missing
  verification, ambiguity, thought/action divergence, outcome-level
  verification. Bounded analysis throughout (8k chars/turn, shingle
  prefilter before SequenceMatcher).
- **`attributor.py`** — fuses detections: score = ln(MAST prior odds) +
  Σ ln-likelihood-ratios of each detection's confidence. Two weak
  independent detections accumulate; a rare-mode prior can be outrun by
  strong evidence. `explain_fusion` prints the arithmetic.
- **`taxonomy.py` / `mastdata.py`** — the 14 MAST failure modes (ids,
  labels, base rates, fixes) and the MAST-Data conversion pipeline that
  feeds the gold benchmark (`docs/mast-bench-multi.jsonl`).
- **`explain.py`** — the taxonomy→human bridge: `explain FM-x.y` deep
  dives (definition, published share, fixes) with the detector column
  derived from the live registries — every detector class carries its
  `mode_id`, so the bridge cannot drift from the code.

### Quality gates on attribution

- **`distill.py`** — `evaluate_multi` (set-based P/R/F1 with Wilson
  intervals), `check_floors` (regression floors), judge-training export.
- **`benchgate.py` / `scripts/bench_gate.py`** — the attribution
  gate, shipped in the package (`approximately bench-gate DATASET
  --floors F`, non-finite floors refused) with the script as a shim:
  gold corpus (n=27, `docs/bench-floors.json`) + synthetic fixture
  (n=180, `docs/bench-synth-floors.json`, generated by
  `scripts/make_synth_corpus.py`). A composite `action.yml` runs the
  same gate in any repo. Floors make silent detector regressions
  fail CI.

## Replay and repair

- **`replayer.py`** — re-execute recorded steps against the live
  environment or a patched executor; A/B diff proves a fix.
- **`align.py` / `diff.py`** — Needleman-Wunsch over normalized action
  sequences; `diff --json` carries per-entry similarity;
  `first_fault` pinpoints the earliest material divergence
  (`bisect FAILED SUCCESS`).
- **`regress.py`** — turns a failed run into a self-contained pytest
  guard (`approximately test`).
- **`repair.py`** — searches the smallest validated intervention set
  that clears attribution (or honestly reports "unrepairable").
- **`counterfactual.py`** — do(step=∅) experiments separating root
  causes from symptoms.

## Analysis layer

`anomaly.py` (median/MAD latency z-scores) · `cluster.py` (recidivist
clustering) · `context.py` (context-budget forecasts, `optimize`
binary-search) · `drift.py` (PSI action drift) · `precursor.py`
(failure prediction from history) · `streaming.py` (live in-flight
risk monitor).

## Fleet operations

- **`fleet.py`** — multi-store survey (failure rates, Theil-Sen trend
  verdicts), HMAC-signed webhooks, `--watch` digest loop (daily JSONL
  snapshots), `--trend` day-level analytics.
- **`query.py`** — recursive-descent DSL over stores (eval-free,
  depth/length capped) with `--stats` aggregates.
- **`doctor.py`** — store health: corrupt records, ledger tamper, stale
  locks, digest gaps; `--fix` cleans hygiene artifacts.
- **`mcp_server.py`** — the whole toolkit as an MCP stdio server
  (JSON-RPC 2.0, zero dependencies; a `resources` surface plus a
  tool inventory grouped by concern — store access, attribution and
  explanation, verification, comparison, prediction and analysis,
  fleet health, triage, metrics). The authoritative count and list
  live in `mcp_server.py`'s `_TOOLS` and are pinned by the tests
  (`test_v48`); docs deliberately avoid restating totals so they
  cannot drift.
- **`toolscan.py`** — static analysis of MCP tool descriptions
  (homoglyphs, bidi, injection); CI runs it against our own tools.
- **`cli.py`** — every surface above as a subcommand, including the
  ops pair: `status` (one-glance overview: health, top modes,
  triage tallies, last failure + chain verdict, optional fleet
  trend) and `annotate` / `annotations --verdict` (the triage log).
  All analysis commands take `--json`; the MCP surface mirrors them
  1:1.

## Interfaces

- **`cli.py`** — every capability as a subcommand; `main(argv)` is also
  the test seam.
- **`contrib/`** — framework adapters (LangChain/LangGraph, OpenAI
  Agents SDK, CrewAI, LlamaIndex, AutoGen, Pydantic AI, Google ADK),
  each a thin capture seam - hook-based where the framework offers
  one, post-hoc transcription where it does not.
- **`demo*.py`** — scripted failing agents powering the 30-second tour
  and the doc artifacts (`scripts/make_docs_artifacts.py`).

## Invariants worth keeping

1. **Zero dependencies** in the core; extras stay optional and lazy.
2. **Attribution never hard-fails** — judge absence, corrupt records,
   torn digests all degrade gracefully to rules-only or empty results.
3. **Detector families stay exclusive** (prose vs tool) — cross-family
   firing would double-label every failure.
4. **Every measurement carries its uncertainty** — Wilson intervals on
   benchmarks, floors with documented slack, synthetic numbers never
   quoted as real-world performance.
5. **Every parser boundary treats its input as hostile** — caps,
   prefilters, seeded fuzz tests (`tests/test_v45_fuzz.py`).
